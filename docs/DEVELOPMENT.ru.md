| `legacy/header-only-reference/` | Старые эксперименты, исключённые из сборки |

## Соглашения API

Расширяйте публичный API без нарушения существующих вызовов. Внутренние
детали не должны попадать в устанавливаемый заголовок. Реализация Go
определяет совместимость формата, но не является зависимостью библиотеки.
Сжатые байты могут отличаться; результат распаковки, обработка чанков,
CRC, конечный размер и семантика индексов должны совпадать.

Для повторных операций используйте `minlz_workspace`: она сохраняет
буферы и хеш-таблицы. Рабочая область изменяема; параллельным операциям
нужны отдельные экземпляры. Освобождайте объекты соответствующими
функциями уничтожения. Результаты поиска и указатели на блоки действуют
только во время функции обратного вызова.

Функции возвращают `minlz_status`. Проверяйте каждый вызов с возможной ошибкой:

| Статус | Значение |
| --- | --- |
| `MINLZ_OK` | Успех |
| `MINLZ_CORRUPT` | Повреждённые или недопустимые данные |
| `MINLZ_CRC` | Несовпадение CRC |
| `MINLZ_TOO_LARGE` | Превышение ограничения размера |
| `MINLZ_UNSUPPORTED` | Возможность недоступна |
| `MINLZ_INVALID_LEVEL` | Неизвестный уровень сжатия |
| `MINLZ_DST_TOO_SMALL` | Недостаточная ёмкость выходного буфера |
| `MINLZ_IO` | Ошибка ввода-вывода или выделения памяти |
| `MINLZ_SEARCH_TABLES_UNUSABLE` | Строгий поиск не может использовать таблицу |
| `MINLZ_SEARCH_STOP`, `MINLZ_SEARCH_FORWARD` | Управление поиском из функции обратного вызова |

## Изменения и проверка

Меняйте горячие циклы небольшими шагами и измеряйте результат на характерных
данных. Добавляйте исходники в CMake, проверяйте публичное поведение,
документируйте изменения API, параметров и формата на двух языках.
Не включайте оптимизацию под локальный процессор по умолчанию.
Сохраняйте переносимую реализацию и проверяющие обёртки ассемблерных функций.
См. [тестирование](TESTING.ru.md) и [оптимизацию](OPTIMIZATION.ru.md).
