# Оптимизация

Русский · [English](OPTIMIZATION.md) · [На главную](../Readme.ru.md)

Совместимость важнее скорости. Сохраняйте переносимый C, проверки обёрток
и хвостов, повторное использование памяти, проверку CPUID и состояния ОС
перед AVX. Не включайте `-march=native` по умолчанию.

## Критерии принятия

Оптимизация по умолчанию должна пройти модульные тесты и матрицу
принудительных реализаций, переносимую сборку ASan/UBSan и взаимные
проверки сжатия и распаковки с Go. Для заявлений об ускорении нужны
полная матрица с семью выборками и уточняющие повторы из руководства
по [измерениям](PERFORMANCE.ru.md).
На измеряемом наборе требуется `C encoded_size <= Go encoded_size`.
Регрессии CRC, конечного размера, индексов, проверок повреждений
и результата распаковки недопустимы.

Оптимизируйте поиск совпадений, очистку таблиц и использование регистров
на основании измерений. В декодере отдельно рассматривайте литералы,
короткое перекрытие, заполнение повторами и большие копирования.
Не обходите проверки границ ради измерений. Изменения потоков и индексов
должны сохранять владение памятью и восстановление после ошибок.

## Необязательные реализации (по умолчанию OFF)

| Параметр | Поведение и цена |
| --- | --- |
| `MINLZ_ENABLE_EXPERIMENTAL_L2_SEARCH` | Кандидат GNU/Clang amd64 с преобразованным хешированием и распределением регистров для L2 512 КиБ–2 МиБ; порядок обновления и сжатые байты сохраняются |
| `MINLZ_ENABLE_HUGEPAGE_WORKSPACE` | Подсказки Linux о больших страницах повторно используемой памяти; дополнительное выравнивание, память и однократный переход |
| `MINLZ_ENABLE_READSEEKER_BUFFER_TRANSFER` | Передача проверенных буферов рабочей области в кеш индексированного читателя без дополнительного копирования при промахе |

Для кандидата L2 сохраняется принятая реализация. Побайтового совпадения
недостаточно для включения: проверяйте соседние размеры, задержки
малых блоков и полную матрицу операций.

Область для больших страниц первоначально выровнена на 64 байта.
При четвёртом подходящем использовании amd64-путь пытается выделить
память с выравниванием 2 МиБ и вызвать `MADV_HUGEPAGE`.
Рост сбрасывает счётчик, сброс рабочей области сохраняет память.
Ошибка выделения или отказ подсказки сохраняют старый буфер.
Другие платформы и переносимая реализация используют обычную память.
Принятая подсказка не доказывает физическое выделение больших страниц.
Четвёртый вызов и удерживаемую память измеряйте отдельно; указатели
на scratch нужно получать заново после каждого сжатия.

Буферы передаются только после проверки длины и CRC. Представление raw-блока
начинается через четыре байта от начала выделенной памяти; кеш сохраняет
указатель владельца. Для слишком большого входного scratch и малых raw-блоков
используется ограниченное копирование. Ошибка распаковки должна сохранять
прежний кеш. Меняется владение памятью, а не сжатые байты.

Проверяйте OFF/ON для каждого параметра отдельно, затем сочетания.
Ускорение прогретой рабочей области или кеша не означает прохождения
всей матрицы. Покрытие описано в [тестировании](TESTING.ru.md),
соглашения API — в [разработке](DEVELOPMENT.ru.md).
