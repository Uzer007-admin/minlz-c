# Подготовка выпуска

Русский · [English](RELEASE_CHECKLIST.md) · [На главную](../Readme.ru.md)

## Исходники и состав поставки

- Начните с чистой копии. Не включайте в коммиты результаты сборок,
  локальные отчёты, архивы переноса, учётные данные и настройки машины.
- Проверьте все публикуемые ветки и теги, сообщения коммитов и старые
  версии файлов. Проверяйте архив исходников вместе с HEAD.
- Сохраняйте уведомления об авторских правах и лицензии стороннего кода.
- Обновляйте оба Readme и обе языковые версии затронутых руководств.
- Согласуйте спецификации формата с заявленной версией совместимости.

## Сборка и корректность

- Release для Linux и Windows проходит CTest.
- Проходят принудительные portable, SSE4.2, asm, AVX2 и проба AVX512.
- Переносимая Linux-сборка ASan/UBSan проходит без asm и intrinsics.
- Тесты совместимости с Go проходят на зафиксированной ревизии эталона.
- CLI сохраняет байты при сжатии и распаковке блоков и потоков,
  включая stdin/stdout.
- До смены значений по умолчанию необязательные реализации отдельно
  проверены с OFF и ON.

## Установка

- Установите библиотеку, заголовок, CLI, пакет CMake, спецификации,
  лицензии и документацию на двух языках.
- Соберите внешний `tests/package_consumer` через `find_package`
  и запустите проверку распаковки. Проверьте переносимость установки.
- Проверьте относительные ссылки в исходной и установленной документации.

## Производительность и версия

Для заявлений об ускорении запустите полную матрицу с семью выборками
и уточняющие повторы для default, SSE4.2 и asm. Сохраните оборудование,
компилятор, ревизию Go, параметры сборки, размеры и подтверждённые проигрыши.
См. [измерения](PERFORMANCE.ru.md).

Перед выпуском версии согласуйте `project(minlz_c VERSION ...)`,
`MINLZ_VERSION_STRING`, ожидаемую версию в тесте пакета и описание выпуска.
Создавайте тег после завершения проверки этой версии. Публикация снимка
исходников не означает приёмку всех необязательных реализаций
или достижение всех целей производительности.
