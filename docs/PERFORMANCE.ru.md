# Измерения производительности

Русский · [English](PERFORMANCE.md) · [На главную](../Readme.ru.md)

Измеряйте размер и скорость вместе. Фиксируйте процессор, ОС, компилятор,
параметры сборки, выбранную реализацию, ревизию Go и прогрев рабочих
областей. Один набор данных или одна машина не доказывают общего
превосходства по скорости.

## Сравнительная программа

Настройте `MINLZ_GO_REPO` и запустите на свободной Linux-машине:

```sh
./build-release/minlz_perf --samples 7 \
  --go-oracle --go-speed --strict-go-size --candidate-gate
```

Поддерживаются `MINLZ_GO_REPO`, `MINLZ_GO_COMPAT` (исходник помощника)
и `MINLZ_GO_COMPAT_BIN` (готовая программа). Предварительная сборка
снижает затраты на запуск. Матрица включает блоки, потоки, операции
с индексом и прогретое чтение ReadAt.

## Отчёты и подтверждение результатов

Обёртке для отчётов нужен Python 3:

```sh
python3 tools/minlz_report.py \
  --build-dir build-release --go-repo /path/to/minlz \
  --samples 7 --gate-profile full --keep-going \
  --fail-on-go-win --official-gate
```

По умолчанию отчёты создаются локально в `docs/perf-reports/`
и игнорируются Git. Для другого каталога используйте `--out-dir`.
CSV, Markdown, HTML и исходный вывод сохраняют измерения и действующие
ограничения процессорных инструкций. Строки ниже 1,03× перепроверяются:
семь выборок в трёх раундах. Подтверждённая скорость ниже 1,0× или размер
C больше Go приводят к отрицательному результату. Начальное число
выигранных строк не отменяет ошибок подтверждения.

Для отдельных случаев используйте `--corpus`, `--level` и `--rounds 3`.
`--level` принимает значения C: -1, 0, 1, 2, 3. `--iterations` нужен
для явного управления циклами; иначе число повторений подбирается
автоматически. `--alternate-go-order` уменьшает влияние порядка замеров.

## Процессорные ограничения

Повторите отчёт с `MINLZ_FORCE_CPU=sse42` и `MINLZ_FORCE_CPU=asm`.
Обёртка собирает помощник Go с `GOAMD64=v2`, отключает AVX в Go
и ограничивает AVX-реализации копирования и очистки glibc в Linux.
Программа Go v3/v4 не может отказаться от обязательных инструкций через
`GODEBUG`. Для заявлений о работе без AVX сохраняйте соответствующие
метаданные отчёта. Выбираются программные пути на имеющемся процессоре,
другой процессор не эмулируется. Ограничения glibc не действуют на UCRT Windows.

## Дополнительные измерения

```sh
./build-release/minlz_thread_perf input.bin corpus-name 2 4 3 7
```

Многопоточный декодер выдаёт CSV: операция, набор, уровень, потоки,
размеры, коэффициент сжатия и минимальная, медианная, максимальная скорость.
Закрепляйте процессы за сопоставимыми ядрами, разделяйте базовую
и проверяемую конфигурации. Для изменений рабочих областей и кеша
используйте порядок A/B/B/A. Издержки запуска, выделение памяти и задержки
в хвосте распределения измеряйте отдельно от прогретой пропускной способности.
